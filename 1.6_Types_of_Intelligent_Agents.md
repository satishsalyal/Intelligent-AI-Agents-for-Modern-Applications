## 1.6.1 Introduction

Intelligent agents are classified according to how they perceive their environment, represent information, make decisions, and select actions to achieve their objectives. Different types of agents use different mechanisms to determine what action should be performed in a particular situation.

Some agents follow predefined condition–action rules, while others maintain an internal representation of the environment, plan actions towards a goal, evaluate alternative outcomes, or improve their behaviour through experience. The choice of agent type depends on the complexity of the problem, the availability of information, the degree of uncertainty, and the level of intelligence required.

> In classical Artificial Intelligence, five major types of intelligent agents are commonly discussed:
>
> 1. **Simple reflex agents**
> 2. **Model-based reflex agents**
> 3. **Goal-based agents**
> 4. **Utility-based agents**
> 5. **Learning agents**

> [!NOTE]
> These categories are particularly useful for understanding the evolution of agent architectures, from basic rule-based systems to agents capable of learning and adapting. They are conceptual categories rather than mutually exclusive implementations: a practical AI system may combine several of these approaches.

>

| # | Agent Type | Description |

| 2 | **Model-Based Reflex** | Uses percepts and an internal state or model. |

## 1.6.3 Simple Reflex Agents

### Definition

A simple reflex agent selects an action based only on the current percept, using predefined condition–action rules. It does not explicitly use a history of previous percepts or maintain an internal model of the environment.

A condition–action rule is commonly expressed as:

```
IF condition, THEN action
```

For example:

- IF the room temperature is above the threshold, THEN switch on the cooling system.
- IF an obstacle is detected immediately ahead, THEN stop the robot.
- IF a submitted form is missing a required field, THEN display a validation message.

### Architecture of a simple reflex agent

| Stage | Description |
|---|---|
| **Environment and Sensors** | Observe the current situation |
| **Current Percept** | Identify the relevant condition |
| **Condition–Action Rules** | Match the percept with a predefined rule |
| **Action** | Execute the selected response |

The action changes the environment, which can produce a new percept.

### Example: Automatic cooling system

A simple temperature-control agent might use the following rule:

```python
temperature = float(input("Enter room temperature: "))
if temperature > 30:
    print("Cooling system ON")
else:
    print("Cooling system OFF")
```

Sample output:

```
Enter room temperature: 34
Cooling system ON
```

> [!TIP]
> This program is a simplified illustration of a condition–action policy. A real control system would also consider sensor reliability, temperature thresholds, hysteresis, and equipment safety.

### Characteristics

| Advantages | Limitations |
|---|---|
| Easy to design and implement. | Does not inherently learn from experience. |
| Fast response to familiar situations. | Cannot reliably distinguish situations that look identical now but require different actions because of earlier events. |
| Requires relatively little computational power. | |
| Works well when current observations are sufficient. | |

### Advantages and limitations

The main advantage of a simple reflex agent is its simplicity. It is appropriate for environments with clear, stable rules and limited uncertainty.

Its principal limitation is dependence on the current percept. If the agent cannot observe a relevant condition, it may choose an inappropriate action. It can also behave poorly when the environment requires memory, planning, or reasoning about hidden information.

> [!NOTE]
> **Suitable applications:** Basic thermostats, rule-based alert systems, simple automated controls, and form-validation systems.

## 1.6.4 Model-Based Reflex Agents

### Definition

A model-based reflex agent maintains an internal state that represents relevant aspects of the environment. It uses the current percept, previous state, and knowledge about how the environment changes to update this internal representation.

This approach is useful when the environment is only partially observable. The agent may not be able to observe everything directly at a particular moment, so it uses past information and an internal model to estimate the current situation.

### Why is an internal model needed?

Consider a robot moving through a building. Its camera may not currently show a room it visited earlier, but information about its previous location and movement can help it estimate where it is now.

A model-based agent uses two important elements:

- **Internal state:** A representation of relevant information about the current environment.
- **Transition model:** Knowledge or an approximation of how the environment changes when actions occur.

A simplified state-update expression is:

```
s_t = f(s_{t-1}, a_{t-1}, o_t)
```

where:

- `s_t` is the updated internal state.
- `s_{t-1}` is the previous internal state.
- `a_{t-1}` is the previous action.
- `o_t` is the current observation.
- `f` is the state-update function.

This expression describes a general update process. Actual implementations may use logical rules, state machines, probabilistic models, or learned representations.

### Architecture

| Stage | Description |
|---|---|
| **Current Percept** | Information received from sensors or tools |
| **State Update** | Combine current observations with previous state |
| *Previous state and transition model* | |
| **Updated Internal State** | Estimate the current situation |
| **Condition–Action Rules** | Choose a response using the updated state |
| **Action** | |

### Example: Robot vacuum cleaner

A simple robot vacuum may move forward until it detects an obstacle. A model-based robot can additionally maintain information about visited areas, obstacles, its approximate position, and the locations it has yet to clean.

This information allows it to avoid repeatedly cleaning the same area and to make better decisions when some parts of the environment are not currently visible.

### Characteristics

- Maintains an internal state.
- Uses previous information along with current observations.
- Can operate in partially observable environments.
- Makes decisions using a representation of how the environment changes.
- May still rely on predefined rules rather than explicit goal search or utility optimisation.

### Advantages and limitations

Model-based reflex agents handle hidden or changing environmental conditions better than purely reactive agents. However, their effectiveness depends on the accuracy of their internal state and transition model. Incorrect assumptions or outdated state information can lead to poor decisions.

> [!NOTE]
> **Suitable applications:** Robot navigation, equipment monitoring, inventory tracking, and automated systems that must remember previous states.

## 1.6.5 Goal-Based Agents

### Definition

A goal-based agent selects actions by considering whether they help achieve a specified goal. Rather than responding only through fixed condition–action rules, it evaluates possible future states and chooses actions that move the environment towards a desired outcome.

Goal-based agents often use search algorithms, planning methods, or state-space exploration to identify a suitable sequence of actions.

### Goal-based decision-making

A goal-based agent typically:

1. Observes the current environment.
2. Represents the current state.
3. Identifies the desired goal state.
4. Generates possible actions.
5. Predicts or evaluates the consequences of those actions.
6. Selects a suitable action or plan.
7. Monitors progress towards the goal.

### Architecture

| Element | Description |
|---|---|
| **Perception and Current State** | |
| **Goal** | Desired state or outcome |
| **Model of Actions** | Possible actions and their effects |
| **Search and Planning** | Find a sequence of actions that can reach the goal |
| **Execute and Evaluate** | Perform actions and check progress |

### Example: Route-planning agent

Suppose an agent must find a route from location A to location B. It represents locations as states and roads as possible transitions. Its goal is to reach location B.

The agent may use a search algorithm such as breadth-first search for an unweighted graph, or A* search when an appropriate heuristic is available.

A simplified state-space representation is:

| A | B | D |
|---|---|---|
| Start | Intermediate | Goal |

**Illustrative route:** A → B → D

The agent selects a sequence that reaches the destination. If several routes reach the goal, a basic goal-based agent may accept any suitable route, depending on its search procedure. Choosing the fastest or cheapest route requires additional criteria, which are central to utility-based decision-making.

### Characteristics

- Uses an explicit goal or desired outcome.
- Considers possible future states.
- Can compare alternative action sequences.
- Often uses search and planning algorithms.
- Can revise a plan when the environment changes.

### Advantages and limitations

Goal-based agents are more flexible than agents that rely exclusively on fixed rules because their decisions depend on the objective. However, planning may require considerable computation, particularly when the number of possible actions and future states is large.

A goal alone also does not necessarily specify which of several successful outcomes is preferable.

> [!NOTE]
> **Suitable applications:** Route planning, puzzle solving, automated scheduling, robotic task planning, and multi-step workflow execution.

## 1.6.6 Utility-Based Agents

### Definition

A utility-based agent evaluates possible outcomes using a utility function and selects actions according to their expected desirability.

Utility provides a way to compare alternatives when several actions can achieve a goal but differ in cost, time, risk, quality, or other important factors.

A goal-based agent may ask, "Can this action achieve the goal?" A utility-based agent additionally asks, "How desirable is the outcome compared with other possible outcomes?"

### Utility function

A utility function assigns a numerical value to an outcome or state:

```
U(s) = Utility or desirability of state s
```

A higher utility value usually represents a more desirable outcome under the chosen criteria.

When outcomes are uncertain, the agent may evaluate expected utility:

```
EU(a) = Σᵢ P(sᵢ | a) · U(sᵢ)
```

where:

- `a` is a candidate action.
- `s_i` is a possible outcome.
- `P(s_i | a)` is the estimated probability of that outcome after action `a`.
- `U(s_i)` is the utility assigned to that outcome.

A utility-based agent may choose the action with the highest expected utility, subject to safety, resource, and policy constraints. This expression is a simplified model; real systems may use more complex objectives and uncertainty estimates.

### Architecture

| Stage | Description |
|---|---|
| **Current State and Candidate Actions** | |
| **Predict Possible Outcomes** | Estimate the consequences of each action |
| **Evaluate Utility** | Compare outcomes using defined criteria |
| **Select the Preferred Action** | Choose the highest-value permitted option |

### Example: Intelligent delivery agent

A delivery-planning agent may compare three routes:

| Route | Estimated time | Estimated cost | Reliability |
|---|---|---|---|
| **Route A** | 30 minutes | ₹120 | High |
| **Route B** | 25 minutes | ₹180 | High |
| **Route C** | 40 minutes | ₹80 | Moderate |

The best route depends on the priorities defined by the system.

- If delivery time is the dominant criterion, Route B may be preferred.
- If cost is the dominant criterion, Route C may be preferred.
- If both cost and reliability matter, Route A may provide a better balance.

> [!CAUTION]
> The numbers are illustrative. In a real implementation, the utility function would need to represent the application's actual requirements, and safety or legal constraints would take precedence over utility maximisation.

### Characteristics

- Evaluates the desirability of alternative outcomes.
- Can balance multiple objectives.
- Supports decision-making under uncertainty.
- Can compare options even when several achieve the same goal.
- Depends on the quality of its utility function and outcome estimates.

### Advantages and limitations

Utility-based agents are suitable for complex decisions involving competing priorities. Their principal challenge is defining a meaningful utility function. Poorly chosen weights or incomplete criteria can produce undesirable decisions even when the calculations are performed correctly.

> [!NOTE]
> **Suitable applications:** Resource allocation, delivery optimisation, recommendation systems, energy management, and decision support.

## 1.6.7 Learning Agents

### Definition

A learning agent improves some aspect of its behaviour through experience, feedback, or data. Rather than relying entirely on fixed rules or a static decision policy, it can modify its behaviour as it acquires relevant information.

Learning agents are especially valuable in environments where conditions change or where it is difficult to specify every possible situation in advance.

A classical learning-agent architecture contains four principal components.

### Components of a learning agent

| Component | Responsibility |
|---|---|
| **Learning Element** | Improves the agent using feedback or experience |
| **Performance Element** | Selects actions based on the current policy or knowledge |
| **Critic** | Evaluates performance using feedback or a defined measure |
| **Problem Generator** | Suggests exploratory actions that may provide useful new experience |

These components have distinct responsibilities:

#### 1. Performance element

The performance element selects actions using the agent's current policy, rules, or learned model. It is the component that directly determines the agent's behaviour.

#### 2. Learning element

The learning element updates the performance element using feedback or experience. Depending on the architecture, it may update parameters, rules, a policy, a model, or stored knowledge.

#### 3. Critic

The critic evaluates how well the agent is performing. Its feedback may be based on a reward signal, task-completion measure, human evaluation, or comparison with expected results.

#### 4. Problem generator

The problem generator proposes exploratory actions that may produce useful information. Exploration can help the agent discover better strategies than those already known.

> [!NOTE]
> Not every modern learning system explicitly implements these four components as separate modules, but the framework provides a useful conceptual model.

### Example: Personalised learning system

A personalised educational agent may recommend practice questions to a student. It can analyse performance on previous exercises and adjust the difficulty or topic selection.

A simplified learning cycle is:

1. Recommend a practice question.
2. Observe the student's response.
3. Evaluate whether the student answered correctly.
4. Update the estimate of the student's mastery.
5. Select a suitable next question.
6. Continue adapting as new evidence becomes available.

> [!TIP]
> Such a system should use sufficient evidence before drawing conclusions. A single incorrect answer may reflect an ambiguous question or a temporary mistake rather than a lack of understanding.

### Learning approaches

| Learning approach | Basic principle | Example |
|---|---|---|
| **Supervised learning** | Learns from labelled examples | Classifying support requests |
| **Unsupervised learning** | Finds patterns in unlabelled data | Grouping similar customer queries |
| **Reinforcement learning** | Learns from rewards or penalties | Learning a control policy in a simulated environment |
| **Feedback-based adaptation** | Updates behaviour using observed outcomes | Adjusting practice-question difficulty |

### Advantages and limitations

Learning agents can improve performance when suitable training data or feedback is available. However, learning introduces challenges involving data quality, computational cost, evaluation, bias, and unpredictable behaviour.

Learning also does not guarantee improvement. An agent can learn incorrect patterns from poor data or an unsuitable reward signal. Changes should therefore be evaluated and monitored, especially in high-impact applications.

> [!NOTE]
> **Suitable applications:** Adaptive education, recommendation systems, robotics, fraud detection, predictive maintenance, and intelligent assistants with explicitly designed learning mechanisms.

## 1.6.8 Comparative Analysis of Intelligent Agent Types

The following table compares the five major types according to their principal decision-making mechanisms.

| Feature | Simple Reflex | Model-Based Reflex | Goal-Based | Utility-Based | Learning |
|---|---|---|---|---|---|
| **Current percept** | Essential | Essential | Essential | Essential | Usually essential |
| **Internal state** | Not inherently maintained | Maintained | Often maintained | Often maintained | Depends on design |
| **Condition–action rules** | Central mechanism | Commonly used | May be used | May be used | May be learned or adjusted |
| **Explicit goal** | Not required | Not required | Central | Usually part of evaluation | Depends on design |
| **Outcome comparison** | Limited | Limited | Evaluates goal achievement | Evaluates desirability | Depends on learned policy |
| **Planning** | Usually absent | Usually limited | Commonly used | Commonly used when needed | Depends on design |
| **Learning from experience** | Not inherent | Not inherent | Not inherent | Not inherent | Defining capability |
| **Typical complexity** | Low | Low to moderate | Moderate to high | Moderate to high | Varies widely |
| **Example** | Threshold-based controller | Robot tracking internal state | Route finder | Route optimiser | Adaptive tutor |

> [!IMPORTANT]
> A learning agent can also be goal-based or utility-based. Learning describes how behaviour can improve, while goal-based and utility-based approaches describe how actions may be selected. These categories therefore overlap.

## 1.6.9 Selecting the Appropriate Agent Type

The appropriate agent type depends on the requirements of the application.

| Use a simple reflex agent when | |
|---|---|
| Conditions are clearly observable, rules are stable, and the required response is straightforward. | |

| Use a model-based reflex agent when | |
|---|---|
| The environment is partially observable and the agent must maintain information about previous states. | |

| Use a goal-based agent when | |
|---|---|
| The system must achieve a specified outcome by selecting among possible action sequences. | |

| Use a utility-based agent when | |
|---|---|
| Several possible outcomes must be compared according to cost, time, quality, risk, or other preferences. | |

| Use a learning agent when | |
|---|---|
| The system needs to improve or adapt its behaviour using data, feedback, or experience. | |

> [!TIP]
> In practice, the best solution may combine several approaches. For example, an intelligent warehouse robot could maintain an internal model of its location, plan routes to delivery points, compare routes by time and energy consumption, and learn improved navigation policies from experience.

## 1.6.10 Relationship Between Classical Agents and Modern AI Agents

The five classical agent types provide a conceptual foundation for modern agentic AI systems, including agents built around Large Language Models (LLMs).

Modern agents may combine:

- LLM-based reasoning to interpret instructions and generate candidate plans.
- Planning mechanisms to decompose complex tasks into manageable steps.
- Tool use to retrieve information or interact with external systems.
- Memory to maintain context and task progress.
- Feedback and evaluation to identify errors and revise actions.
- Learning mechanisms to improve behaviour where explicitly supported.
- Policy controls to constrain actions and protect users and systems.

For example, a research assistant may interpret a research question, retrieve relevant papers, organise the evidence, generate a synthesis, and check whether the draft's claims are supported by the retrieved sources.

Such an agent can exhibit goal-based behaviour, use utility-like criteria to prioritise sources, maintain an internal task state, and employ learning components if the system is designed to support them. However, using an LLM alone does not guarantee reliable planning, persistent memory, or autonomous execution. These capabilities depend on the complete system architecture.

---

## 1.6.11 Conclusion

The classification of intelligent agents explains how AI systems differ in the mechanisms they use to select actions.

Simple reflex agents respond through predefined rules. Model-based reflex agents maintain internal state to deal with partially observable environments. Goal-based agents select actions to achieve desired outcomes, while utility-based agents compare the desirability of alternative outcomes. Learning agents improve their behaviour through data, feedback, or experience.

These approaches form a useful progression from straightforward condition–action behaviour to more flexible decision-making. Nevertheless, they are not mutually exclusive: practical systems can combine internal models, goal-directed planning, utility evaluation, and learning within a single architecture.

Understanding these types prepares the reader to examine how agents are structured, how their components communicate, and how modern AI systems integrate language models, tools, memory, and planning.
